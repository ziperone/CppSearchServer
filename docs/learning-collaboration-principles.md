# 项目学习协作原则

本项目的目标不是背诵每一行代码，而是达到能解释架构、能独立改动关键路径、能定位问题，并能在面试中讲清设计取舍的程度。

## 固定节奏

1. 先架构，后核心手写：先理解模块职责、输入输出和数据流，再写稳定的关键函数。
2. 先跑通，后重写：先得到可验证版本；接口稳定后，关闭参考手写核心单元并运行测试。
3. 只重复训练高价值模块：网络事件分发、HTTP 解析、倒排索引、LRU 缓存等核心路径需要反复练习；构建、日志、字符串拼接等外围代码以理解和会改为目标。
4. 每个模块闭环：明确问题与边界 -> 实现/手写 -> 编译或测试 -> 复盘 -> 用费曼法讲解 -> 阶段提交 GitHub。

## AI 协作边界

- AI 可以实现骨架和非核心细节，但必须说明其在系统中的位置与可验证方式。
- 核心函数先给出接口、数据流和伪代码；由学习者手写，再进行 review、补边界与测试。
- 判断掌握程度以能解释、能修改、能排错、能手写简化版为准，而不是逐行记忆全部实现。

## 当前项目的优先手写模块

- `createListenSocket`、非阻塞 `accept` 循环、`epoll_wait` 事件分发。
- HTTP 请求行与 query 解析、`writeAll`。
- 倒排索引构建、查询排序。
- LRU 的 `get`、`put`、淘汰逻辑。
