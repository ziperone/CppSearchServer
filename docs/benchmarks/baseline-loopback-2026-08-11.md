# 回环基线压测：2026-08-11

## 环境与负载

- 服务器与压测客户端：同一台 Linux 主机，`127.0.0.1` 回环访问。
- 主机：80 个逻辑 CPU，62 GiB 内存。
- 构建：Release。
- 服务：`cpp_search_server 18085 data/docs`。
- 请求：`GET /search?q=epoll`。
- 持续时间：每轮约 30 秒。
- 当前数据集很小，仅用于网络、HTTP、内存索引和短连接路径的初始基线，不代表大规模语料性能。

## 初步结论

- c16 的两次已知运行结果为 39,481.14 与 40,544.90 QPS，波动约 2.7%，说明单次结果不应被当作精确结论，后续每档负载至少重复 3 次。
- `c1 -> c64`：QPS 从约 2 万提升到约 5 万，说明并发连接能提高吞吐；但 P99 从 88us 升至至少 1.58ms，排队延迟显著增加。c1 的 QPS 是单连接串行请求-响应-关闭循环的吞吐，并非服务器总吞吐上限。
- `c16 -> c64`：QPS 从约 4.05 万提升到约 4.95 万，增幅约 22%，说明 c16 尚未充分施压。
- `c64 -> c256`：QPS 差异约 0.05%，可视为正常测试波动，吞吐已经进入平台。
- P99 从 748us 增至 1.98ms，再增至 5.92ms；c256 没有带来吞吐收益，却显著增加排队和长尾延迟。
- 当前负载下的吞吐饱和拐点约在 c64，而非服务器在所有负载、所有数据规模下的绝对极限。
