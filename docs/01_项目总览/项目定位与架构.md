# 项目定位与架构

## 一句话定位

面向个人求职知识库的 C++ 高并发本地文档检索服务：将 Markdown/TXT 按标题切块、构建倒排索引，并以 HTTP 接口提供低延迟关键词检索。

它不是“复现一个 WebServer”。Reactor 是网络基础设施；检索服务解决的是求职资料、项目记录、面试经验和技术笔记分散在本地文件中、难以快速定位的问题。

## 用户、输入与输出

- 用户：正在整理个人知识库的求职者或开发者。
- 输入：本地 Markdown/TXT 文档和 `/search?q=epoll%20reactor` 请求。
- 输出：命中文档片段、标题路径、来源和排序分数的 JSON。
- 边界：当前是关键词检索，不宣称已实现向量检索、RAG 或分布式部署。

## 当前架构

```text
HTTP 客户端
  -> 主网络线程：监听、accept、把连接交给一个子网络线程
  -> 子网络线程：epoll 监听连接读写与 eventfd
  -> 连接对象：HTTP 缓冲、Keep-Alive、超时、同连接响应顺序
  -> 工作线程池：解析请求、检索、构造 JSON
  -> worker-local L1 / Redis L2 / 内存倒排索引
  -> eventfd 把结果交回原子网络线程
  -> 原网络线程写回 HTTP 响应
```

## 关键边界

1. 网络线程独占 socket、读写缓冲、epoll 状态和连接计时器。
2. 工作线程只做业务计算，完成后通过线程安全任务队列和 `eventfd` 回传。
3. 同一连接一次只处理一个请求，保证响应与请求顺序一致；不同连接可以并发进入不同工作线程。
4. 文档启动时构建内存索引，查询期不遍历磁盘。

## 已验证能力

- 非阻塞 socket、epoll、Keep-Alive、半关闭、空闲连接回收。
- 主 Acceptor + 多子 Reactor + WorkerPool。
- Markdown/TXT 切块、分词、倒排索引、多关键词召回和 TopK 排序。
- worker-local L1 与 Redis L2，可故障回源；默认无缓存。
- Release 环境 CTest `20/20` 通过；基准、阶段指标和 perf 采样均有记录。

## 不夸大的表述

- 不说 Redis 提升了当前单机 QPS；当前小型内存索引下三轮对照恰好相反。
- 不说项目已分布式；当前仅验证 Redis 可跨实例共享缓存结果。
- 不说已接入真实密文检索；这属于下一阶段，接入、测试和数据齐全后才能写进简历。
