# 检索模块：性能优先设计决策

## 项目定位

CppSearchServer 的检索能力服务于个人求职知识库，并为后续 Agent 提供可引用证据。首版不追求通用搜索引擎或复杂 NLP，而要展示 C++ 后端的低延迟、高并发和可观测优化能力。

## 保留的检索能力

- 文档按标题切为可引用 `DocumentChunk`。
- 统一 tokenizer 用于文档建索引和查询解析。
- 轻量英文停用词过滤，仅过滤 `the`、`and`、`is`、`uses` 等无区分度词；技术词不作为停用词。
- 多词查询采用 OR 召回，按命中词覆盖数优先，再按轻量 TF-IDF 分数排序。
- 返回固定 TopK，避免构造和排序全部候选结果。
- 中文首版保留原文短语/子串匹配作为补充，不引入分词库。

## 明确暂不做

- 不引入向量数据库、embedding 或 LLM 参与召回。
- 不引入 SimHash。它更适合近重复文档检测，不是当前关键词召回的必要路径。
- 不默认做最小编辑距离拼写纠正。它对技术词容易误修正且计算成本更高；仅在零命中时作为可选回退能力评估。
- 不实现完整通用搜索语法、复杂布尔查询或中文 NLP。

## 性能路径

1. 启动时加载文档并在内存中构建索引，查询路径不做磁盘扫描。
2. 索引构建完成后保持只读，为后续多线程查询提供稳定共享数据。
3. 查询复杂度主要与查询词数量和各词 posting list 长度相关，而不是全库文本长度。
4. 使用有界 TopK 堆替代对全部候选结果完整排序。
5. 后续以 LRU 本地缓存、Redis 二级缓存、线程池和压测数据逐步优化。
6. Benchmark 记录 QPS、P50/P95/P99 延迟、候选数、命中数、内存占用与缓存命中率。

## 下一实现阶段

实现 `SearchService`：

```text
q
-> tokenize + stop words
-> 每个 term 查询 posting list
-> chunk_id 聚合 coverage 和 TF-IDF 分数
-> TopK
-> SearchResult
```
